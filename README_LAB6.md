# ArtChain — ЛР №6, вариант 21

Галерея загружается с сервера через GET, ставка отправляется формой через POST. Каталог и ставки хранятся в db.json, а не в localStorage или массиве внутри клиентского JavaScript. Публикация NFT из ЛР5 сохранена и тоже работает через сервер.

## Установка в существующий проект

1. Сохраните копию своей папки проекта.
2. Распакуйте содержимое этого архива в папку ArtChain с заменой совпадающих файлов. Сохраните свою папку images: архив содержит обновление программы и не заменяет ваши изображения.
3. Откройте терминал в папке, где лежит package.json.
4. Нужен Node.js 22.12+ (либо актуальная LTS-версия 24). Проверка: `node -v`.
5. Выполните:

```powershell
npm install
npm run dev
```

Откройте http://127.0.0.1:5173/catalog.html. Один npm run dev запускает и Vite, и API. Оставляйте терминал открытым; Ctrl+C завершает оба процесса.

Для отдельного запуска в двух терминалах: `npm run server` и `npm run dev:ui`.

**В этой лабораторной нельзя запускать сайт двойным щелчком по HTML или через Live Server.** По заданию нужны ES-модули, Vite и настоящий HTTP API. Открывайте адрес Vite. При открытии каталога браузер выполняет GET /api/nfts; Vite перенаправляет запрос на json-server.

## Проверка работы

- Откройте каталог: сначала показывается «Загрузка галереи…», затем карточки с сервера.
- Нажмите «Сделать ставку». Откроется форма с выбором NFT, вашим именем и суммой.
- Укажите сумму строго выше текущей цены. В DevTools → Network виден POST /api/bids со статусом 201. В запросе есть nftId, bidder и amount. В ответе — серверный идентификатор ставки, сумма, валюта и дата.
- Сервер проверяет текущую цену, сохраняет ставку в bids, обновляет price и bids у NFT. Затем клиент выполняет GET /api/nfts и обновляет каталог.
- Обновите страницу: цена и счётчик сохраняются, поскольку данные находятся в db.json.
- Форма checkout.html тоже размещает ставку и выполняет POST /api/bids. Ссылки из карточек передают выбранный NFT.
- Форма публикации внизу каталога отправляет POST /api/nfts; новый NFT появляется первым.
- Проверка сбоя: запустите API и Vite отдельными командами; остановите только API через Ctrl+C и обновите каталог. Появится ошибка и кнопка «Повторить загрузку». Запустите API снова и нажмите кнопку.
- При отсутствии сети или HTTP-ошибке данные из localStorage не подставляются. Ошибка показывается честно, форма не сообщает об успешной ставке без подтверждения сервера.

## Сборка

```powershell
npm run build
```

Все пять HTML-страниц собираются в dist. Изображения автоматически копируются из images в public/images и затем в dist/images.

Проверка сборки:

```powershell
npm run server
```

В другом терминале:

```powershell
npm run preview
```

Откройте http://127.0.0.1:4173/catalog.html. API также должен работать: dist содержит клиент, а db.json и сервер запускаются отдельно.

## Файлы

- src/main.js — инициализация, асинхронная загрузка, обработчики форм, делегирование, состояния интерфейса.
- src/api.js — Fetch API, GET и POST, response.ok, разбор JSON, тайм-аут и ошибки.
- src/ui.js — класс NFT, построение DOM, отрисовка каталога и сообщений.
- src/model.js — проверки данных и суммы.
- src/styles.scss — стили каталога и форм; кнопки закреплены снизу карточек.
- server.cjs — сервер на json-server с проверкой и сохранением ставок.
- db.json — серверная база, коллекции nfts и bids.
- vite.config.js — пять HTML-точек входа и прокси /api.
- scripts/dev.mjs — совместный запуск Vite и API, работает без shell-команд Windows/Linux.
- scripts/prepare-assets.mjs — копирование изображений для сборки.
- tests/lab6.test.mjs — проверка API, записи на диск и восстановления после перезапуска, конфликта одновременных ставок, форм и DOM, индикатора загрузки, ошибок и повторной попытки.

## Данные прошлой работы

База содержит исходные 15 NFT из ЛР4. Пользовательские NFT из localStorage ЛР5 автоматически на сервер не переносятся: заново опубликуйте нужные работы формой. Не заменяйте свой уже изменённый db.json при повторном обновлении программы — в нём находятся опубликованные NFT и ставки.

## Git

Ветка не создавалась, удалённый репозиторий не изменён. Если продолжаете существующий проект, используйте свою ветку main. Старый js/main.js заменён совместимым пустым файлом, чтобы монолит ЛР5 не исполнялся случайно: новая точка входа — src/main.js. Каталог css оставлен для старых внешних ссылок; активные стили ЛР6 подключаются из src/styles.scss.

Не добавляйте node_modules, dist и public/images в Git — они создаются при установке/сборке. Исходную папку images и db.json храните в репозитории.
